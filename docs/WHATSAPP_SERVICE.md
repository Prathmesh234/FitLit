# Private WhatsApp self-chat

FitLit can use an optional linked-device bridge for low-latency questions from
WhatsApp's **Message yourself** chat. It is a private prototype built on the
pinned `baileys` package, not Meta's official Cloud API. Baileys may break when
WhatsApp changes its web protocol, and unofficial automation can carry account
restriction risk. Use an account whose risk profile you accept.

## Data boundary

- The bridge accepts only live, direct messages authored by the paired account
  in its own self-chat. It rejects groups, status, newsletters, broadcasts,
  other accounts, history sync, and messages generated by FitLit.
- At most the latest five user/assistant turns exist in Node memory. Message
  bodies are sent to Python through stdin and are never written to the ledger,
  process arguments, or durable application storage. The shared provider
  harness uses one mode-`0600` request file inside a private temporary
  directory and deletes the entire directory after each reply.
- `data/state/whatsapp-ledger.json` stores only bounded message IDs, statuses,
  timestamps, and outbound IDs for deduplication and loop prevention.
- `data/state/whatsapp-auth/` contains login-equivalent Signal keys and
  linked-device credentials. It is gitignored and forced to owner-only modes.
- The shared provider harness remains authoritative: Copilot defaults to
  GPT-5.6 Sol at high reasoning effort, receives bounded context plus grounded
  local summaries, and returns qualitative text and evidence selections.
- WhatsApp receives plain text. Evidence-only XLSX/DOCX artifacts are decoded
  in memory, hash-checked, sent as documents, and then discarded.

## Install and pair

Requires Node 20+ and npm:

```bash
npm --prefix whatsapp-bridge ci
```

Set only the trusted account number in private `.env` using E.164 syntax:

```ini
FITLIT_WHATSAPP_TRUSTED_USER_E164=your-private-e164-number
FITLIT_WHATSAPP_CONTEXT_MESSAGES=5
FITLIT_WHATSAPP_ENABLED=false
```

Render the pairing QR:

```bash
npm --prefix whatsapp-bridge run pair
```

On the phone, open **WhatsApp → Settings → Linked Devices → Link a device** and
scan the terminal QR. The command exits after the linked-device session opens.
Never copy, publish, or back up the generated auth directory to an untrusted
location.

After pairing, set `FITLIT_WHATSAPP_ENABLED=true`, then install/start the units:

```bash
uv run python scripts/preflight.py
sudo uv run python scripts/install_services.py --install --start
systemctl is-active fitlit-whatsapp.service
```

Open **Message yourself** and send a normal question—no command prefix is
needed. Initial support covers text and media captions; inbound media bytes are
not downloaded. FitLit replies in the same chat and attaches requested
evidence workbooks/documents.

## Operations

```bash
journalctl -u fitlit-whatsapp.service -f
systemctl restart fitlit-whatsapp.service
systemctl disable --now fitlit-whatsapp.service
uv run python scripts/preflight.py
```

Logs contain operational event classes, never message bodies. To revoke the
bridge, remove the linked device in WhatsApp, stop the service, and delete
`data/state/whatsapp-auth/`.
